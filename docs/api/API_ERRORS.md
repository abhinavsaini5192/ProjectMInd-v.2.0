# ProjectMind API Error Handling & Error Code Catalog

## 1. RFC 7807 Problem Details Standard

ProjectMind implements the **IETF RFC 7807 (Problem Details for HTTP APIs)** specification for all API error responses. Clients receive consistent, machine-readable JSON error documents across all endpoints, whether errors originate from transport validation, security checks, rate limiters, or domain engine operations.

### Canonical Error Schema
```json
{
  "type": "https://projectmind.ai/errors/validation-failed",
  "title": "Validation Failed",
  "status": 422,
  "code": "VALIDATION_FAILED",
  "detail": "The request body failed schema validation. 2 issues detected.",
  "instance": "/v1/features",
  "requestId": "req_84920482",
  "timestamp": 1758963500000,
  "errors": [
    {
      "field": "name",
      "message": "Field 'name' is required and cannot be empty",
      "code": "REQUIRED_FIELD"
    },
    {
      "field": "confidenceScore",
      "message": "Field 'confidenceScore' must be a number between 0.0 and 1.0",
      "code": "INVALID_RANGE"
    }
  ]
}
```

### Schema Property Definitions

| Property | Type | Description |
|---|---|---|
| `type` | `string (URI)` | Absolute URI reference identifying the specific problem type. |
| `title` | `string` | Short, human-readable summary of the problem category. |
| `status` | `number` | The HTTP status code generated by the origin server for this occurrence. |
| `code` | `string` | Standardized uppercase ProjectMind `ApiErrorCode` enum string. |
| `detail` | `string` | Human-readable explanation specific to this occurrence of the problem. |
| `instance` | `string` | The URI path of the resource where the error occurred. |
| `requestId` | `string` | Unique request tracking identifier for debugging and log correlation. |
| `timestamp` | `number` | Unix epoch timestamp in milliseconds when the error occurred. |
| `errors` | `array` (optional) | Array of field-level validation errors or child diagnostic issues. |

## 2. API Error Code Catalog

The following table lists all canonical `ApiErrorCode` values, their standard HTTP status code mapping, and typical cause:

| ApiErrorCode | HTTP Status | Description / Common Cause |
|---|---|---|
| `BAD_REQUEST` | 400 | General client error or malformed request syntax. |
| `INVALID_ARGUMENT` | 400 | Missing, invalid, or conflicting query or path parameter. |
| `MALFORMED_INPUT` | 400 | Unparseable JSON body or invalid character encoding. |
| `UNSUPPORTED_VERSION` | 400 | Requested API version is unrecognized, unsupported, or retired. |
| `UNAUTHENTICATED` | 401 | Missing, invalid, or expired API key or Bearer token. |
| `FORBIDDEN` | 403 | Principal authenticated, but lacks permission for requested action. |
| `INSUFFICIENT_SCOPE` | 403 | Attempt to access a resource outside the caller's workspace boundary. |
| `NOT_FOUND` | 404 | Target resource (workspace, repository, feature, session) does not exist. |
| `CONFLICT` | 409 | Resource state conflict (e.g. concurrent write or duplicate entity). |
| `IDEMPOTENCY_CONFLICT` | 409 | Concurrent in-flight request or key reused with different payload. |
| `ALREADY_EXISTS` | 409 | Entity with the given unique identifier or slug already exists. |
| `PRECONDITION_FAILED` | 412 | Precondition header (e.g. `If-Match`) evaluation evaluated to false. |
| `PAYLOAD_TOO_LARGE` | 413 | Request body exceeds configured payload byte limit. |
| `UNPROCESSABLE_ENTITY` | 422 | Syntactically valid request could not be processed due to semantic errors. |
| `VALIDATION_FAILED` | 422 | One or more fields failed declarative schema validation rules. |
| `RATE_LIMITED` | 429 | Client exceeded request budget. Includes `Retry-After` header. |
| `INTERNAL_SERVER_ERROR` | 500 | Unhandled server error or unexpected domain engine failure. |
| `NOT_IMPLEMENTED` | 501 | Endpoint or requested capability is recognized but not supported yet. |
| `SERVICE_UNAVAILABLE` | 503 | Platform is undergoing maintenance or essential backing service is down. |
| `GATEWAY_TIMEOUT` | 504 | Upstream downstream service or query execution exceeded timeout. |

## 3. Domain Engine Error Mapping

[`ApiErrorMapper`](file:///c:/Users/Mummy/Desktop/bakwas/ProjectMind/src/api/errors/ApiErrorMapper.ts) translates internal domain exceptions into clean RFC 7807 responses without leaking stack traces or storage internals:

```
[Domain Exception]
       │
       ├── ContextError (e.g. BUDGET_EXCEEDED) ───► 422 UNPROCESSABLE_ENTITY
       ├── FeatureNotFoundError ──────────────────► 404 NOT_FOUND
       ├── KnowledgeConflictError ────────────────► 409 CONFLICT
       ├── AgentTaskTimeoutError ─────────────────► 504 GATEWAY_TIMEOUT
       ├── SecurityAuthorizationError ────────────► 403 FORBIDDEN
       └── Unhandled Generic Error ───────────────► 500 INTERNAL_SERVER_ERROR
```

### Production Security Protections
In production (`NODE_ENV === 'production'`):
1. Sensitive internal stack traces are completely stripped from error objects.
2. Generic 500 errors display a safe, redacted message (`"An internal server error occurred"`).
3. The underlying root cause exception is securely logged to internal telemetry tagged with the `requestId` for debugging by authorized platform engineers.
