# Memory Provenance & Origin Tracking

## 1. Provenance Classifications

Every memory records its origin via [MemoryProvenance](file:///c:/Users/Mummy/Desktop/bakwas/ProjectMind/src/memory/project/models/MemoryEnums.ts):
- `DEVELOPER`: Directly authored by a developer or team lead (e.g. ADRs, commit comments).
- `REPOSITORY`: Extracted from code structure, build configs, or package definitions.
- `DOCUMENTATION`: Sourced from checked-in architecture manuals or design docs.
- `AGENT`: Generated or suggested by an AI agent or LLM.
- `VERIFICATION`: Verified by automated test suites or static analysis passes.
- `SYSTEM`: Generated by ProjectMind runtime components.
- `HISTORY`: Extracted from version control commit history.
- `IMPORTED`: Ingested from external project management tools (e.g. Jira, GitHub Issues).
- `INFERRED`: Deduced from patterns across multiple repositories.
- `UNKNOWN`: Unclassified source.

## 2. Provenance Protection Invariant

```
┌─────────────────────────────────────────────────────────────┐
│                 CRITICAL PROVENANCE RULE                    │
├─────────────────────────────────────────────────────────────┤
│  AGENT_REPORTED can NEVER automatically become              │
│  AUTHORITATIVE or SYSTEM_VERIFIED without explicit human    │
│  or test verification.                                      │
└─────────────────────────────────────────────────────────────┘
```

When an agent proposes a candidate with `AGENT` provenance claiming `AUTHORITATIVE` authority, [ProjectMemoryManager.promoteCandidate](file:///c:/Users/Mummy/Desktop/bakwas/ProjectMind/src/memory/project/services/ProjectMemoryManager.ts) automatically downgrades it to `NON_AUTHORITATIVE` unless an explicit human override is provided.
